#### v0.2.8 修 v0.2.7 编辑框三行"乱七八糟"对齐 bug（仍是 v0.2.7 的插入/缺失图形化意图）

- **现象**：v0.2.7 编辑框里「引物/参考/结构」三行序列错位、乱成一团，看不出插入/缺失。
- **根因（致命）**：v0.2.7 的 `toHtml` 单元格用了 `display:inline-block;width:22px` 和 `border-radius`——Java `HTMLEditorKit` **不支持**这些 CSS，宽度被忽略；再叠加三字符 `---` 与中文 `凸`/`─`（中文是双宽字符，彻底砸乱等宽对齐）→ 三行全错位。
- **修复**：回到**真·等宽网格**——每列只放**一个字符**（`Monospaced` 字体天然等宽，自然对齐），颜色/底色用 `<span style>`（v0.2.5 已验证可用），彻底去掉 `inline-block`/`border-radius`/`---`/中文。
  - 插入（引物比参考多碱基）= 引物行**青底字符**（即"环/凸起"）；缺失（引物比参考少）= 参考行**橙底字符**（"缺口/环"的另一半）。
  - 结构行全 ASCII 单字符：`^`=插入、`_`=缺失、`.`=一致、空格=突变断口。
  - 三行前缀统一 4 字符宽，确保列对齐。
- **附带**：新增 `demo_indel_primers.bed`（NC_000001.11 上 DEMO_INS=插入、DEMO_DEL=缺失 两条示例），可直接「导入 BED」查看效果。
- track 上的青色环(drawOval)/橙色短竖标记不变（真实图形，无此问题）。

#### v0.2.9 修编辑框抖动 + 滑动图形序列不同步

- **现象 A（抖动/反复滚动条）**：编辑对话框打开后，序列框/「突变比对」区持续抖动、反复出现滚动条，体验卡顿。
- **根因 A**：①「突变比对」`mmPane` 被包进可滚动 `JScrollPane` 且横向填充，HTML 内容高度一变 → 外层整体 `JScrollPane` 滚动条出现 → 可用宽度变窄 → `mmPane` 重排变高 → 滚动条再出现……**布局抖动死循环**；② 每次改坐标都同步跑全体系二聚体评估（`evaluateOneAgainstAll` + Top-5 形状对齐），重计算阻塞 EDT。
- **修复 A**：`mmPane` 改为**固定尺寸 + 禁用横/纵滚动条**（内容恒 3 行，不再驱动外层布局抖动）；序列框禁横向滚动条；`updatePreview` 加 **90ms 防抖**（合并高频事件，一次刷新搞定）；序列框写入改用 **安全 setter**（先摘自身 DocumentListener、仅内容变化才写、写完装回），彻底斩断 setText→listener→重算的回环与闪烁。
- **现象 B（滑动不同步）**：在 track 上拖动/缩放引物图形后，引物序列不随之变化（仍是旧位置的序列）。
- **根因 B**：`PrimerEditTool` 松手时调 `refreshSequence`，但引物带 `seqLocked=true`（手动编辑或 BED 导入锁定的）会**直接跳过重新读参考基因组**，于是坐标变了序列不变。
- **修复 B**：拖动/缩放（及方向键移动）改变坐标后，先 `seqLocked=false; seq=null;` 再 `refreshSequence` —— 按新坐标**重新取参考序列**，同时**作废此前手动编辑/导入锁定的突变信息**（符合预期：挪了位置就该按新位置重算）。键盘移动同样处理，行为统一。

#### v0.2.7 编辑框"点图形进去空白"修复 + 插入/缺失图形化（凸起块 / `---` 缺口）

- **需求**：点引物图形进编辑框却显示空白「—」不符合预期（内存里理应有序列）；且引物与参考存在"起泡/环/缺失"结构时，应在编辑框用图形表示——插入（引物比参考多碱基）= 引物行**凸起一块**，缺失（引物比参考少碱基）= 引物行**`---` 缺口**。
- **根因①（空白）**：`updatePreview` 只在 `seqLocked && seq != null` 时才用内存序列，否则回退读参考；且对 **− 链已锁定引物**会把 `existing.seq`（已是 5'→3' 实际寡核苷酸）又做一遍 `revComp` —— 双重反向互补导致序列错乱；参考读空时一路 silent 空白。
- **修复①**：`updatePreview` 改为**优先用内存里已存的序列**（无论是否锁定，非空即用），且 `existing.seq` 不再二次反向互补；两者皆空时给出明确提示（"请确认参考基因组已加载/坐标正确，或重新保存"）而非空白「—」。
- **修复②（图形化）**：`PrimerMismatch.toHtml` 重写——引物行插入碱基渲染为**青色凸起块（环）**，缺失位置渲染为**橙色 `---` 缺口**；参考行互补显示；新增"结构"指示行（`凸`=插入、`─`=缺失、`.`=一致、空格=突变断口）。单元格统一 22px 宽保证三行严格对齐。

#### v0.2.6 比对加 gapped 对齐：标记居中对准碱基 + 插入(环)/缺失符号

- **需求**：① 箭头上的红色竖线落在碱基"左边缝隙"而非碱基中心，视觉错位；② 引物若比参考多出碱基（与参考形成"环/凸出"），应能体现成另一种符号。
- **根因**：原 `compare` 是逐位（positional）比对，`gpos = start+i` 取的是碱基的**左边缘**坐标；且无法表达插入/缺失（长度不等只截断前 N 位，插在中间的多余碱基无从表示）。
- **改为全局比对（Needleman-Wunsch）**：`PrimerMismatch.compare` 重写为 gapped 对齐，产出对齐后的 oligo/ref（含 `'-'` 空位）与每列 `kind[]`（新增 `INSERTION=5`/`DELETION=6`）。
- **标记居中**：每列返回 `markerCoord[]`（该碱基**居中**基因组坐标 = `refPos + 0.5`），track 上红竖条/环精确对准碱基中心，不再落在缝隙。`PrimerTrack.drawPrimer` 改用 `markerCoord` 绘制。
- **三类偏差用不同符号**（`PrimerTrack.drawPrimer` + 编辑框 toHtml + 悬停 tooltip 三处一致）：
  - 突变/不覆盖简并（MISMATCH / DEGENERATE_MM）→ **红竖条 + 顶部小方块**（沿用）。
  - 插入 = 引物比参考多出的碱基（与参考形成环）→ **青色小环（drawOval）** 画在箭头上方；编辑框指示行用青色 `o`，oligo 行青底青字。
  - 缺失 = 引物比参考少了该碱基 → **橙色短竖**；编辑框指示行用橙色 `x`。
- **编辑框比对显示**（`toHtml`）：三行（oligo / ref / 指示）改用等宽 `span`（强制 7px 宽，杜绝中英文/符号宽度不一错位）；指示行 `.`=一致、空格=突变、`o`=插入(环,青)、`x`=缺失(橙)；图例同步更新。
- **悬停 tooltip**（`getValueStringAt`）：序列按对齐逐位着色（突变红/简并紫/插入青/缺失橙），并新增「比对: …」指示行，附突变/插入/缺失/简并计数。
- **轻量缓存**：`compare` 按「基因组id+坐标+链+序列」签名缓存，避免每次重绘重复取参考序列；切换参考基因组后调 `clearCache()`。
- 版本号 v0.2.6；README 版本头 + 本变更日志。

#### v0.2.2 编辑模式单击引物常驻选区（与非编辑模式一致）
- 背景：此前在**编辑模式**下点击某条引物，选区（贯穿全高的淡色框 + 红线参考线）只在「按住/拖拽期间」显示，松手即消失；而普通模式点击引物选区会常驻。用户希望两种模式行为一致——点一下就出现、且保持显示。
- 根因：`PrimerEditTool.mouseReleased` 在拖动释放时**无条件调用 `clearGuides()`**（把 `selBox=false` 并隐藏 ruler），把刚点出来的选区当即抹掉；而 `mousePressed` 命中引物分支只 `setSelected` 没同步 `guides` 区间。
- 修复：
  - `mousePressed` 命中引物分支在 `setSelected(hit)` 后补 `setGuides(frame, hit.start, hit.end)`，点中即画框并把选区区间同步给 `guidePositions`（轨道内选区绘制/primer3 预填读取）。
  - `mouseReleased` 删除无条件 `clearGuides()`，改为在拖动分支内用最终位置 `setGuides(rf, dragging.start, dragging.end)` 重画——单击或拖拽结束后选区都保留。空白点击仍走原 `mousePressed` 的 `clearGuides()` 清除（行为不变）。
- 非编辑模式的选区逻辑由独立的 `ShiftSelector` 处理，未受影响。

#### v0.2.1 全局异常捕获（诊断「点了没反应、无报错」）
- 背景：IGV 用 `javaw` 启动，异常只进 stderr（不可见）；Swing 在 EDT 事件处理器里抛错会被静默吞掉，表现为「右键点了不弹窗、也没任何报错」，极难排查。
- 修复：在 `PrimerPlugin.init()` 安装全局异常捕获——`EventQueue.push` 包装 AWT 事件分发 + `Thread.setDefaultUncaughtExceptionHandler`，任一未捕获异常都会：① 完整堆栈追加写入 `~/.igv_primer/error.log`；② 弹对话框显示「异常类：消息」。重入安全（reporting 标志防止递归）。
- 用途：本次「无法添加引物 / 其他窗口也弹不出」即此类静默失败；v0.2.1 后重启 IGV 复现，异常会直接弹窗，把对话框文字或 `~/.igv_primer/error.log` 内容发回即可定位。

#### v0.2.0 平铺设计（Tiling 覆盖目的区域）
- 右键「primer3 设计 ▸」新增第 5 项**「平铺设计（Tiling 覆盖目的区域）...」**：给定一个大的目标区域（如整个基因），自动划分为互相重叠的产物窗口序列，逐窗设计，把整段区域覆盖住（重测序 amplicon 方案）。
- 参数：目标区域（选区/视口预填，**不钳屏幕**——平铺就是给大区域用的）、产物长度 min/max（默认 400–700bp）、相邻重叠（默认 100bp）、每窗对数（默认 1）、常规引物参数；对话框内实时预览划窗数。

- 结果：所有窗口的成功引物对汇总进一个结果表，T 编号连续（T1、T2…；分组内名为 `分组_T1_F/R`），勾选落轨；相邻窗重叠区挑中同一引物时自动合并去重；无解窗口在提示里逐个列出（W编号+坐标）。

### 编辑操作（进入编辑模式即生效；**所有引物均可拖拽/缩放**，空白处拖动 = 正常平移视图）
- **悬停引物两端**（±6px）= 双向箭头光标 → 拖动 = 缩放引物长度
- **悬停/按住引物本体** = 移动光标 → 固定长度左右拖动，放开即固定新位置
- **单击** 引物 = 选中（出现橙色端点手柄 + 高亮框）

- **双击** 引物 = 直接弹出编辑框（可改坐标/方向/角色/测序长度/配对）

- **拖动 / 缩放中** 贯穿数据面板全高的 **红色 ruler 线**（glass pane 叠加层，对齐参考序列轨/其他 track），松开即消失，便于对照坐标对齐

### 键盘快捷键（精确移动选中引物）
选中一条引物后（橙色端点手柄出现），用方向键**精确移动**，不会像鼠标拖动那样因手抖而乱跑：
- **← / →**：整条引物左 / 右移动 1 bp（按住 **Shift** = 10 bp），固定长度平移，松手即重算 Tm/GC/二聚体。
- **↑ / ↓**：上 / 下移动一行（视觉布局），自动设置手动行号（优先级高于自动布局），便于把引物错开分行。
- 前提：处于「引物编辑模式」。**v0.1.20 起默认不自动进入**（防误触），需右键 Primers 轨「进入引物编辑模式」或点工具条按钮激活；未选中引物时方向键仍是 IGV 原生的视图平移。
- 在对话框输入框内打字时快捷键自动失效，不会影响输入。

### 默认参数与配对
- 添加/编辑对话框：**R1、R2 测序长度默认 0**（允许 0，纯引物不显示延长区）。
- 对话框内 **"保存配置"** 按钮：把当前 长度/方向/角色/R1/R2 写入 `~/.igv_primer_defaults.properties`，下次打开自动沿用。
- **配对引物（支持 1:N 一对多）**：在对话框"配对引物名称"填**多条引物名，逗号分隔**（如 `P002,P003,P004`）。所有列出的引物 + 本条共享同一个**配对组 ID**（即画连线 + 算异源二聚体，组内任意两条都参与二聚体评估）。后加的引物填已存在组里的任一成员名 → 自动**并入该组**（不会新建组）。导出 BED 时配对组 ID 写入 name（如 `P001|R1|read0|aG1`），**导入时按组 ID 自动复原多对配对**，无需手动重连。

### 实时参数（每条引物下方）
`P001 F Tm60 GC55 R1+150nt`；**任一参数 fail → 红色外框 + 红色参数**。
判定：长度 18–30nt；Tm 55–65°C（SantaLucia NN + 50mM Na⁺，500nM）；GC 30–75%；hairpin ΔG > -3.5；self-dimer ΔG > -5；任意两引物 3' 互补 ≥4bp 或 ΔG ≤ -5 → 双双标红。

### MFEprimer 质量检查面板（右键直接打开）
- **入口**：右键 Primers 轨 → 「MFEprimer 质量检查」→ 直接弹出综合面板（**非模态**，开着也能继续在 IGV 里拖选区分、改引物，边看边改）。
- **5 个功能按钮**（点哪个跑哪个，结果就地显示在面板内，不弹新窗）：
  - **二聚体**：调用 MFEprimer `dimer -p`（仅 3' 端互补），秒级、不碰基因组。
  - **发夹**：调用 MFEprimer `hairpin`，单序列二级结构。
  - **特异性 (spec)**：脱靶/特异性检查，复用 IGV 当前加载的基因组（大基因组会弹确认框，可选仅含引物染色体）。
  - **覆盖度 (coverage)**：目标/菌株覆盖度分析，同样走 IGV 当前基因组。
  - **质量检查 (qc)**：二聚体+发夹一键快查（**不做脱靶**，避免大基因组慢）。
- **结果区操作**（按钮栏第二组）：分段显示（全部/二聚体/发夹）、「不显示引物序列」开关、ΔG≥阈值筛选（填值→筛选，只留达标的行）、「重新检测」（用当前最新引物重跑，防抖）、「导出报告」（所见即所得导出为 txt）。
- **前置**：首次使用先点面板顶部「⚙ 设置 MFEprimer 路径」按钮，填好 MFEprimer 可执行文件**绝对路径**（带「浏览…」选 exe/bat/sh），确定即生效并持久化；空路径时所有功能按钮会提示先配置。

### 区内 PCR 设计预览（实时跟随视图）
- 区内 PCR 设计弹窗里改字段（产物区间/设计区），**实时预览**：黄色高亮 = 产物（选区）区间，蓝色高亮 = 两侧设计区；缩放/平移视图时高亮实时跟随（玻璃层按当前参考帧从 bp 换算，不缓存像素坐标）。
- 选区时显示**双向箭头**顶住两边，中间以 `1.1kb`/`500bp`/`10.5kb` 形式直接展示选区大小，无需手算。
- 多条引物（如 1-F-多-R）**自动展开分行**，重叠自动开新行，不再叠在一起。

### 显示元素
- 绿色右箭头 = 前向(+)，蓝色左箭头 = 反向(-)；条更窄（行高 30px）
- 引物**下方**浅色虚线小带 = 测序延长区（按 R1/R2 各自 readLen；与引物本体明确分开，不合并）
- **配对引物（共享配对组 ID）**：
  - size==2（常规 R1/R2）强制排在同一行，中间非配对引物自动避让到上下行，互不遮挡。
  - **size>2（一对多）走 hub-spoke 放射式**：起始居中的引物为 **hub**（标 `hub×N` + 小圆点），其余伙伴各占独立上下行；从 hub 中点向每条 spoke 中点画**不同色的放射线 + 方向箭头**，每条标注 `P1/P2…` 区分；选中组内任一引物 → 整组连线加粗高亮。
- 灰色横线 + **PCR 产物长度标注**（含引物长度，v0.1.3）= 同一扩增子 R1-R2 连线；**连线位于两条引物箭头相对的正中间**；两端实心方向三角（按链着：绿=+/蓝=-）指向扩增子内部，直观表示 R1/R2 面对面

```bash
# 1) 准备干净编译基线（剔除旧插件类，避免 classpath 污染）——仅在切换 IGV 版本时需要重做
#    _igv_base.jar = 从目标 igv.jar 剔除 org/broad/igv/primer/* 类 + builtin_plugin_list.txt 注册行
# 2) 编译（JAVA8_HOME / IGV_JAR 环境变量可指定 JDK8 与干净基线 jar）
bash build.sh                 # 编译到 classes/
# 3) 注入到真实 igv.jar（自动备份 + 去签名 + 写注册）
python install.py <目标 igv.jar 路径>     # 给本机/对方的 igv.jar 打补丁
python install.py --package              # 仅打包 PrimerPlugin.jar（分发给他人）
```
- ⚠️ **编译 classpath 必须用干净基线 `_igv_base.jar`，绝不能用已注入插件的 igv.jar**：否则 javac 会解析到陈旧插件类，导致新加的方法/字段"找不到符号"或静默产出缺引用的 class。
- `install.py` 打补丁后的 jar 与仓库 `_test_igv.jar` **等价验证**：注册一致 / 同类字节一致 / 签名已去。
- （旧路径 `deploy.py` 仍保留，基于已知洁净底座 jar 整体重建；现主流程为 `build.sh` + `install.py`。）

### 通用安装器（B 模式：分发给他人 / 重装本机）
```bash
python install.py --package            # 打包本项目 -> PrimerPlugin.jar（仅含自研插件类，不含任何 IGV 类）
python install.py <对方 igv.jar 路径>  # 给对方的 igv.jar 打补丁：自动备份 + 注入 + 去签名 + 写注册
# 不传路径则自动探测常见位置（C:\Program Files\IGV\lib、/opt/igv/lib 等）或当前目录 igv.jar
```
- 安装后对方重启 IGV 即自动加载 `Primers` 轨，**零额外操作**。
- 卸载：用安装时生成的 `igv.jar.bak-<时间戳>` 覆盖回 igv.jar 即可。
- 已 headless 验证：install.py 打补丁后的 jar 与现有改装 jar **完全等价**（注册一致 / 36 个插件类字节一致 / 签名已去 / 含 BoundedPopupMenu）。

## 已知限制
1. Swing 拖拽无法 headless 验证，交互手感需本地 GUI 验收。坐标换算已统一走 IGV 权威 API `frame.getChromosomePosition()`（注意 getScale() 语义是"碱基/像素"）。
2. hairpin/dimer ΔG 为工程估算（非完整折叠算法），数量级判断可靠，精确值以 mfeprimer 复核为准。
3. 需先加载参考基因组才能算参数（没基因组时显示"无序列"红框）。
4. 每对 R1/R2 需手动成对添加（共享配对组 ID 才会画连线/算异源二聚体）。
5. 一对多编辑限制：在对话框修改某引物的"配对引物名称"会**新增**到所属组，但不会自动解除它此前已配对的旧伙伴（如需拆对，清空该引物及旧伙伴的配对字段后重新指定）。导入 BED 按组 ID 复原，无此问题。
6. MFEprimer 各版本 CLI 参数差异较大；插件按 4.x 文档默认参数并回显原始输出，若某子命令在你的版本报"参数不被识别"，把报告里的原始输出反馈即可微调。spec/coverage 需 IGV 已加载参考基因组（直接从当前基因组 dump，无需另找 FASTA）；大基因组（>150Mb）全量建索引较慢，可在弹出的确认框选"仅含引物染色体"。

## v9 更新（右键菜单白板修复）
- **现象**：右键 Primers 轨出现大片白板，命中信息多（含二聚体等指标）时必现。
- **根因**：`IGVPopupMenu` 宽度由其**最宽子项**决定。命中引物的信息行由 `bedName() + metricsSummary()` 拼成（名称/分组/配对/颜色 + Tm/GC/hairpin/self-dimer/异源二聚体/3'互补/FAIL），单行极长 → 整张菜单被撑到数千像素宽，其余短菜单项只占左侧，右侧留白成"白板"。
- **修复**：①新增 `BoundedPopupMenu extends IGVPopupMenu`，覆写 `getPreferredSize()` 把宽度封顶为 `MENU_MAX_W = 320`（与 IGV 原生右键菜单宽度一致，高度不限制）；②信息行超 84 字符自动截断并加 `…`。
- **headless 实测**：同一文本下 原生菜单宽度 **9239px** → 封顶后 **320px**。

## v10 更新（session 丢失兜底：自动保存 + 恢复）
- **现象**：保存 session XML 后再加载，`Primers` 轨不回来。
- **根因（机制使然，非 bug）**：IGV session 只序列化**带 ResourceLocator 的数据轨**（BED/VCF/BAM 等有文件来源的）。PrimerTrack 是插件运行时注入的**内存轨**，`getResourceLocator()` 为 null → 不会被写进 session XML。
- **处理**：加自动保存兜底（而非强改 session 机制）
  - 引物任何改动（增/删/清空/导入）**立即**写盘，`refresh()`（拖动、改色）**节流 1.5s** 写盘 → `~/.igv_primer_autosave.bed`
  - 文件格式与「导出 BED」完全一致（含 `|role|read|g|a|c`），所以能被 `parseBED` **完整还原配对组、颜色、测序长度**
  - 右键新增：「自动保存引物（防丢失）」开关（持久化到配置文件）+「恢复上次编辑（自动保存）」→ 一键回到**可编辑**的 PrimerTrack
- **session 场景用法**：session 加载后发现引物没了 → 右键「恢复上次编辑」即可；长期归档仍建议用「导出 BED」随项目一起存。

### 为什么不直接变成 BED 轨（挂 ResourceLocator 方案的后果）
若给 PrimerTrack 挂上 BED 资源让 session 能保存，加载回来会是 **BED 数据轨**：
- ✅ 能看：位置、名称、`itemRgb` 颜色、链向（strand 列）
- ❌ 不能编辑（拖拽/拖边/双击全失效）
- ❌ 配对连线、1:N 汇聚曲线丢失（BED 轨不画）
- ❌ 测序延长区（R1/R2 read）不显示（BED 只存引物本体区间）
- ❌ Tm/GC/hairpin/二聚体不重算，重叠引物不自动分行（会叠在一起）
- ❌ 且插件 `init()` 仍会新建空 PrimerTrack → 出现**空 PrimerTrack + BED 轨**双轨
